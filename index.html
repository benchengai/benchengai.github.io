01 Released

EmoRE

Meeting audio → an emotion-aware requirements specification.

Gemini 2.5 Pro diarises and transcribes the recording and labels every utterance with one of eight emotions. A second stage writes an IEEE 29148 SRS in which those emotions set conflict level, open issues and priority. A RAG module answers questions across meetings, and reports export to .docx.

Evaluated onAMI Meeting Corpus, four consecutive meetings

02 Released

meeting2srs-lora

A 2.9 MB LoRA filter that cuts what the LLM has to read.

A LoRA-tuned DistilBERT (1.11% of parameters trained, on 1,363 hand-labelled utterances) keeps only the transcript sentences that state requirements. GPT-4o then writes the requirements document, with tokens and latency logged for both paths.

04 In development Flagship

ElicitSense

Meeting recordings → an evidence-linked requirements register.

Transcribes on device, extracts typed requirements under one strict schema (GPT, Claude or a local model), and keeps only items whose quote matches the transcript. Hesitant answers are flagged for follow-up, a cross-meeting register tracks refinements, conflicts and superseded items, and a tool-using agent answers questions with checked citations. Every model is benchmarked on a held-out project for quality, cost and latency.

Live democlick any quote to hear that moment of the meeting · no API key needed

How I build LLM systems

Evaluation first

Gold labels, precision and recall, and regression tests come before prompt tweaks. Results ship with their caveats.

Grounded output

Schema-validated structured output. Every claim cites its source, and code rejects anything it can't verify.

Model proposes, code decides

The LLM suggests labels and links; deterministic code applies state changes, so behaviour stays testable and auditable.

Local-first and private

On-device transcription and LoRA-tuned edge models keep raw audio and sensitive text off the cloud. Only what's needed is sent.
