Evaluation

Every number comes from elicitsense bench and bench-qa runs: each model runs each project three times on identical transcripts. Development set: Harbour Physio (prompts were written against it). Held-out set: Fernhill Bakery (written before any model ran on it). Small synthetic projects; one relation moves recall by 0.11 to 0.14, so treat differences of that size as noise.

Extraction is not where models differ (every API model finds all gold requirements and every quote verifies). Linking requirements across meetings is. Only runs that merge with gpt-6.1-sol, on its own or after gpt-6-luna extracted, kept the held-out project’s unresolved disagreement open in every run. The local model’s held-out bar is not a stable result: on the development set it found almost none.

Routing the cheap model to extraction and the strong one to merging costs about half as much and keeps the unresolved conflict. The local model runs at no per-token cost but is left off this chart (it has no position on a log scale); see the table.

Known gaps the evaluation found

  • A question with a false premise (“why did they decide…” when nothing was decided) was corrected in every answer, but most runs flagged it “not answerable”. The answer schema needs a “premise corrected” outcome.
  • Extraction recall hides status errors: the same merge model finds fewer changes when a smaller model extracted, because a reversed proposal was recorded as confirmed.
  • The local 8B model often wrote its final tool call as text instead of making it.
  • Q&A facts are matched by keywords, which undercounts paraphrases.
